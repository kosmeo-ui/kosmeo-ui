# @kosmeo-ui/demo

A small customer-admin app built entirely from `@kosmeo-ui/react`. It is private and never
published.

```sh
npm run demo                       # from the repo root: Vite dev server
npx nx run @kosmeo-ui/demo:build   # builds the library first, then the app into apps/demo/dist
```

In dev, Vite aliases `@kosmeo-ui/react` to `packages/react/src`, so library edits hot-reload.
`vite build` uses the package's built `dist/`, the way an app installing it from npm would.

## Structure

The app follows [bulletproof-react](https://github.com/alan2207/bulletproof-react):

```
src/
  app/            # provider, router, and one module per route (lazy-loaded)
  components/     # shared app components: the dashboard layout, the error fallback
  config/         # env and route paths
  features/       # auth, customers, dashboard, gallery, settings
    <feature>/
      api/        # one file per request: fetcher, queryOptions, hook
      components/
      utils/
  hooks/  lib/  types/  utils/
  testing/mocks/  # MSW handlers over an in-memory db
```

ESLint (root `eslint.config.mjs`) enforces the rules:

- a feature never imports another feature; routes in `app/` compose them, passing one into
  another as a prop where needed (Settings receives the customer picker that way)
- imports flow one way: shared folders → `features/` → `app/`
- file and folder names are kebab-case
- no import cycles

Imports use the `@/` alias for `src/`. Two repo conventions win over bulletproof's defaults:
import order is the repo's length-sorted order (`npm run sort-imports`), and Prettier uses the
repo's config.

## Mock API

There is no backend. [MSW](https://mswjs.io) intercepts `/api/*` in the browser
(`src/testing/mocks`), serving 240 generated customers and handling the `limit` / `cursor` /
`sort` / `filter[…]` params `InfiniteScroll` and `useInfiniteCursor` send. Changes last until
the page reloads. Set `VITE_APP_ENABLE_API_MOCKING=false` and `VITE_APP_API_URL` to point the
app at a real API instead.

`public/mockServiceWorker.js` is generated by MSW; after upgrading `msw`, regenerate it with
`npx msw init apps/demo/public`.

## Pages

| Page | Shows |
|------|-------|
| Dashboard | `StatCard`, `SummaryRow`, `Table`, `Card` progress, `ProgressBar`, `Alert`, `Tooltip` |
| Customers | `InfiniteScroll` + `useInfiniteCursor`: filters, sort, select, delete, CSV download |
| Customer detail | `Breadcrumbs`, `SectionHeader`, `Tabs`, `Stepper`, `DetailField`, `AddressBlock`, `TagCard`, `ListCard`, `Dropdown`, `Modal`, `ConfirmationModal` |
| New customer | A `Stepper` wizard of `Form`s using most of the inputs |
| Settings | `LanguageSelect`, `SearchList`, date/time inputs, `FileDropZone`, `SecretDisplay`, `RecoveryCodeGrid` |
| Sign-in page | `AuthPage` |
| Component library | Every component, one sidebar page per library category (`/components/<category>`), each example with a "Show code" switch that reveals its source |

The sidebar switch toggles `data-theme` on `<html>` and stores the choice with `useLocalStorage`.
