'@kosmeo-ui/react': minor

`Form` checks each field with the browser's own validation (`pattern`, `minLength`, `type`, `min`/`max`) as well as `required`, and marks only the fields that fail, with `aria-invalid`: fields that pass are no longer outlined in green, which read as "accepted" for values the server could still reject. After the first submit a field is checked again as it's edited, focus moves to the first invalid field, and the message is a banner at the top of the form instead of a toast, which a `Modal`'s overlay covered. A new `error` prop shows the app's own form-level error (such as the server's reason for a 400) in the same place. `Input` takes `pattern`, `minLength` and `maxLength`, and its `error` now marks it `aria-invalid` with a red border and describes it, as `helperText` does. The `k-input-valid`, `k-input-invalid` and `k-form-validating` classes are gone, and so is the `react-toastify` dependency.

Below 640px, `InfiniteScroll`'s and `TableFilters`' filter bar folds behind a "Filters" toggle that counts the filters that are set, and opens one filter to a row, so the table is no longer pushed below the fold on a phone.
